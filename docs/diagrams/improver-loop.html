Flow · your assignment

A fourth option: which policy wording

Today the improver can change the instructions, the model and the reasoning level. The challenge adds the policy wording as a fourth choice, so the improver can try data/policy_wording_short.md.

The notebook edits, in order
  1. Load both wording files into a dict, and add "policy_wording": "full" to version 1.
  2. Give propose_change a policy_wording argument and refuse values outside the allowed list, the same way it refuses models.
  3. Store the choice on the version, and add it to rounds and show_rounds.
  4. In make_agent, build the system prompt from the version's wording, not the global policy_wording.
  5. List the wording choices in read_results so the improver knows it can change them.

The names ALLOWED_WORDINGS and policy_wording as a config field are suggestions. The lab doesn't define them.
