# Tech stack

- `backend/`: FastAPI and SQLAlchemy Core, with each query written once for both databases: Supabase's Postgres when `DATABASE_URL` is set, through psycopg in the `undercover` schema (set with `search_path` on each connection) with a pool of at most 4 connections, and SQLite otherwise, as in the tests. Every API operation has an `operation_id`, a one-line docstring and no optional inputs. Paying a claim is a separate operation that takes the amount; the payout rules are an operation too. The backend calls the agent's service only through `backend/agent_client.py`, and never imports the agent. The answer key is in tables of its own, `handler_decisions` and `held_out_claims`, named only in `backend/db.py` and `backend/evaluations.py`, so that no claim operation reads it.
- `agent/`: a dispatcher and a claim agent on OpenRouter. The dispatcher is a LangGraph graph with no model and no checkpointer: `list_claims` fans out one `Send` per claim to a `work_claim` worker, with `max_concurrency` set to N. The worker has a `RetryPolicy` for LangChain's `ModelRateLimitError` and `ModelTimeoutError`, and an `error_handler` that leaves a claim in progress when those run out and sends any other failure back for one more try, so that no error stops a dispatch. This needs `langgraph>=1.2.18`: before that, `invoke` raised a handled error at the end of a run with several parallel tasks. The claim agent is a hand-written LangGraph graph (`StateGraph`, with agent, tools, outcome, sign-off and pay nodes) that works one claim on its own thread, never a shared thread or a subgraph, since a claim can wait days for a sign-off. It saves its progress after every step with LangGraph's Postgres checkpointer with `durability="sync"`, waits for a handler's sign-off with `interrupt()` and resumes with `Command(resume=...)`. `PostgresSaver` holds a lock around every read and write, so each claim run gets a saver of its own on the process's shared psycopg pool of at most 4 connections in the `undercover` schema, in memory in the tests. Whoever needs a connection waits for one, for up to 120 seconds, rather than fail. The agent stays synchronous, since async Postgres connections don't work with Windows' default event loop. The code is in six parts: `api.py`, the only client of the backend; `harness.py`, everything around the model that knows nothing about claims: the model and its usage, the Langfuse tracing, the checkpointer, the retry policies (LangGraph's `RetryPolicy`), steps from replies and results, and the one refusal message; `tools.py`, every tool; `agents.py`, which builds and runs the claim agent, with the model and the run's id in LangGraph's runtime context, and whose `work(claim_id, run)` is the only place the dispatcher touches the claim agent; `dispatcher.py`, the dispatcher, which runs dispatches and evaluations; and `service.py`, the agent's FastAPI service and its entry point beside the backend, which starts a run in a thread of its own and allows one at a time. The agent reaches claims, documents and instructions only through the backend's API. It uses `openai/gpt-6-luna` with low reasoning effort by default, or the model in the environment variable `MODEL_NAME` if set, such as `openrouter/free`, with no reasoning effort set. Cost comes from OpenRouter's `usage.cost` on each reply. Each claim's thread is traced in Langfuse in one session named after the thread, such as `CLM-1008-3f9a2c1d`, and tagged with its run's id through `langfuse_tags`.
- `dashboard/`: React, Vite and TypeScript.
- `e2e/`: Playwright tests.
- `data/`: the business data the backend starts from. Seeding reads the three named files in `data/evals/`, which hold the answer key, and the agent never sees them.

Python 3.12 with uv, all in the root `pyproject.toml`. Node 26. `.env` holds the OpenRouter key (`OPENROUTER_API_KEY`), the Langfuse keys (`LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY`, `LANGFUSE_BASE_URL`) and Supabase's session pooler connection string (`DATABASE_URL`). `npm run dev` passes it to the backend and the agent's service, `uv run -m agent` loads it itself, and the tests never read it. The agent's service is at `UNDERCOVER_AGENT`, or `http://127.0.0.1:8002` by default.
